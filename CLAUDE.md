## CRITICAL DATA FORMAT RULES — NEVER VIOLATE

```
DATE FORMAT:  DD/MM/YYYY  (British convention — NOT MM/DD/YYYY, NOT YYYY-MM-DD)
              Applied to: combined_output.csv, combined_temperature.csv, combined_humidity.csv
              Correct parse: pd.to_datetime(df['Date']+' '+df['Time'], format='%d/%m/%Y %H:%M')
              Wrong parse:   pd.to_datetime(df['Date']+' '+df['Time'])  ← will silently misparse

HF DATA TIMEZONE:  UTC (ISO 8601) — high_freq_voltage/*.csv files use last_changed column
HOURLY TIMEZONE:   Local (EST/EDT) — combined_*.csv files

VOLTAGE UNIT:      Volts (V) — pack-level bus voltage, 4S configuration
TEMPERATURE UNIT:  °F — hourly files; °C is NOT used in this repo's raw data
CURRENT UNIT:      mA — inferred only, no direct measurement instrument

COLUMN SCHEMA — combined_output.csv:
  Date (str DD/MM/YYYY), Time (str HH:MM), Min (float V), Max (float V)
  Derived: Mid = (Min+Max)/2, Spread = Max-Min

COLUMN SCHEMA — high_freq_voltage/*.csv:
  entity_id (str), state (float V) [also appears as 'voltage' in some files], last_changed (ISO 8601 UTC)
  Load: df.columns = ['entity_id', 'voltage', 'timestamp']

QUANTIZATION:  10 mV sensor resolution on hourly data — values like 13.271V are not real
```

## VALIDATION RULES (run before any data append)

```
V-BATT-1: Capacity delivery
  PASS: ≥ 97%
  FLAG: < 97% → "Unexplained capacity drop — confirm measurement before logging"

V-BATT-2: Parasitic draw
  PASS: 8.8–17.8 mA (±1σ band around 13.3 mA)
  FLAG: Outside band → document in report; check for new equipment additions

V-BATT-3: Voltage spread (hourly data)
  PASS: Spread ≤ 60 mV
  FLAG: > 60 mV → EMI artifact — exclude from averages, note timestamp

V-BATT-4: System efficiency
  PASS: 88–92% (normal seasonal range)
  FLAG: < 88% → report anomaly with context

V-BATT-5: Resting voltage trend
  PASS: Approaching or holding ~13.25–13.27V post-relaxation
  FLAG: Sustained drop > 50 mV below baseline without charge event → investigate

V-BATT-6: New HF file row count
  PASS: Roughly consistent with ~3s cadence × hours in window
  FLAG: < 50% expected rows → data export gap — note but do not discard
```

**Trigger:** New data export from Home Assistant (new weekly HF file(s), extended hourly CSVs).

**Skill reference:** `/mnt/skills/user/engineering-monthly-update/SKILL.md`
→ Section: REPO 3 — Lifepo4-Battery-Banks
→ Follow WORKFLOW steps 1–7 (IDENTIFY → VALIDATE → ENTER → RECALCULATE → DOCUMENT → COMMIT → REPORT)

**Repo-specific steps:**

```
STEP 1 — IDENTIFY
  a. New HF file(s) to add to data/high_freq_voltage/
  b. Extended rows to append to combined_output.csv (and temperature/humidity if applicable)
  c. Confirm new data coverage dates and record counts

STEP 2 — VALIDATE (run V-BATT-1 through V-BATT-6 above)
  a. Parse all new files with DD/MM/YYYY format — confirm no date misparse
  b. Check for EMI spikes (spread > 60 mV) — flag timestamps
  c. Check for charge events — flag and isolate
  d. Confirm HF row count plausible for time window

STEP 3 — COMPUTE METRICS
  a. Run scripts/lifepo4_analysis.py (update STASIS_END / data paths if needed)
  b. Capture before/after for key metrics:
     - MA-60 drift rate (mV/day)
     - Current mean voltage (V)
     - Distance from stasis baseline 13.27V (mV)
     - Total HF sample count (cumulative)
     - Study day count

STEP 4 — UPDATE DATA FILES
  a. Append rows to combined_output.csv (maintain DD/MM/YYYY format, no header repeat)
  b. Append rows to combined_temperature.csv and combined_humidity.csv if new data available
  c. Add new HF file to data/high_freq_voltage/ (weekly naming convention: voltage_data_YYYY-MM-DD_to_YYYY-MM-DD.csv)
  d. Update data/README.md table (file, records, coverage) — keep running totals accurate

STEP 5 — UPDATE FIGURES (if drift rate or voltage chart changed materially)
  a. Re-run lifepo4_analysis.py → regenerate figures/fig*.png
  b. Re-run update_voltage_chart.py → regenerate voltage_chart.html (update paths to repo-relative)

STEP 6 — DOCUMENT
  a. CHANGELOG.md — new [YYYY-MM-DD] entry per changelog format below
  b. README.md — update only if milestone crossed (see §README TRIGGERS)
  c. New report file only if findings warrant (see §REPORT TRIGGERS)

STEP 7 — COMMIT
  CalVer format: git commit -m "2026.MM: Month [N] data — [key finding]"
  Example:       git commit -m "2026.03: Month 5 data — stasis confirmed, drift -4.75 mV/day"
  Rule: One logical change per commit. Never bundle data + config changes.
```
